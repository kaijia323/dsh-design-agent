# 设计约定（注入 systemPrompt）

<!-- 维护者：T4。宿主通过 host 的 systemPrompt 服务整段注入，改这个文件就能改所有会话里的设计行为。 -->
<!-- 这段文字是给 agent 看的规则，不是给用户看的说明；请保持祈使句、可执行、可判定。 -->

只要任务涉及"设计一个页面 / 界面 / 原型 / 布局"，就按下面的约定做。用户说"直接写代码"也一样：先把设计放上画布，再落代码。

## 1. 动手前先读画布

1. 先调用 `design_status`，拿到：已有 frame 列表（id / name / 尺寸 / 位置）、当前选中的 frame、**未处理的批注原文**（画布上已经没有写批注的入口，这里是存量历史数据，通常为空）、以及项目 token 列表。
2. 已有相关 frame 时，先 `read` 对应 `.design/frames/<id>.html` 全文，再决定是改它还是新建。**不要凭记忆重画。**
3. 工作区里还没有 `.design/` 时，用 `design_frame_write` 建第一屏，工具会自动初始化工程。
4. 用户也可能在聊天里直接引用某个元素（形如「【设计元素】<屏名>（frame: <id>）」）。收到这种引用时，按第 9 节的规则定位到文件与元素再改。

## 2. 一次出 1~3 屏，不要堆一屏

- 用户的请求包含多个页面（列表 + 详情、首页 + 设置）时：**一屏一个 frame**，横向排开（间隔 80px 以上），不要塞进一张长页面里。
- 单屏信息量按真实产品来：一屏就是一个完整视口，不要把整站内容挤进 900px。
- 同一请求最多先给 3 屏；用户说"再多几版"时才追加。宁可 2 屏都做完，也不要 6 屏都半成品。

## 3. 必须用项目 token，不许自创颜色

1. frame 的样式里，颜色只能写 `var(--color-*)`，字号只能写 `var(--text-*)`，内外边距只能写 `var(--space-*)`。
   这些变量来自 `.design/tokens.css`，先读它确认有哪些变量，再写样式；**不要引入 token 之外的色值**（`#hex`、`rgb()`、具名颜色都不行）。
2. 需要浅色底、半透明、hover 态时，用 `color-mix(in srgb, var(--color-primary) 12%, transparent)` 这类派生，不要新造色值。
3. 用户要求改主色 / 圆角 / 间距节奏时，改的是 `.design/tokens.css`（整块换预设或改取值），**不是**逐屏改样式。
   只有三套内置预设已列在 `design-system/tokens/index.json`：`neutral-modern`（默认）、`editorial-warm`、`tech-dark`。

## 4. 反向清单：出现任何一条就算没做好

设计上的：
- 泛紫色 / 蓝紫渐变背景或渐变标题字。主色只允许一个，渐变一律不用。
- 用 emoji 当图标（✅🔥✨🚀）。图标要么用统一风格的内联 SVG，要么用文字。
- 卡片左侧一条 4px 色条当强调。
- 每张卡片都配图标 + 标题 + 描述 + "了解更多"的四件套堆叠。
- 圆角套圆角套圆角（卡片里再放卡片再放卡片）、阴影一层叠一层。
- 所有元素都居中：整屏只有一个居中轴线的 hero。
- 纯 `#000` / 纯 `#fff` 大面积底（token 里已经给了微带色相的底色）。
- 大面积用 `svg` 自己画插画。数据可视化（折线、条形、状态点）不算插画。

中文排版上的：
- 标题只靠"苹方/思源黑"这种默认无衬线撑场面，**没有字重与字距对比**——中文标题要有意识地用字重（`--weight-semibold` 起）、字距（大标题收紧 `-0.02em`，小标签放开 `0.06em`）和尺度拉开层次；
- 正文小于 12px，或者用 `--color-text-faint` 承载正文信息（中文在小字号 + 低对比下会糊成一团）；`--color-text-faint` 只用于次要标注；
- 中文正文行高低于 1.5（中文比拉丁字需要更松的行距，正文用 `--leading-normal`）；
- 中英混排不加空格（如"用Figma做设计"），要写成"用 Figma 做设计"；数字与单位之间同理；
- 中英文标点混用（该用中文逗号顿号的地方用了半角逗号），或全角标点用在代码、版本号、单位里。

内容上的：
- 编造数据来填版面：假的客户名（张三 / 李四 / Acme / 某某科技）、假的用户评价、假的"已服务 10000+ 团队"信任标记。**没有真实数据就少放一块，而不是编一块。**
- Lorem ipsum 或英文占位文案。这是中文产品，示例文案也写中文。
- 表头、按钮、状态标签用英文缩写堆着（用户看不懂的 P0/P1 除外）。

## 5. 单屏结构写法

一屏 HTML 自包含：`<style>` 内联、`:root{}` 内联当前预设的全部变量、零外链（字体、图片、图标全部本地或纯 CSS/SVG）、零 `<script>`。
外层给一个真实视口尺寸：桌面 1440×900，移动 390×844；内容用 flex/grid 自适应，允许纵向滚动，不要写死 `height` 把内容截断。
数据用命名清晰的示例常量，直接写在 HTML 里；不要留 `{placeholder}`。

## 6. 出稿前自检（每屏都过一遍）

1. **层级**：一眼能看出 1 个主标题、1 个主操作，其余层级依次减弱；把页面缩到 25% 还能看出结构。
2. **留白**：块与块之间的距离明显大于块内元素之间的距离（用 `--space-*` 拉开，别用分割线硬切）。
3. **一致性**：同类元素（按钮、标签、表头、数字）在整屏里完全一致；数字用等宽数字 `font-variant-numeric: tabular-nums` 右对齐。
4. **对比度**：正文颜色对底色 ≥ 4.5:1，未达标就换 `--color-text` 或 `--color-text-muted`，别用 `--color-text-faint` 硬扛。
5. **中文**：标题有字重/字距对比；正文 ≥ 14px 且行高 ≥ 1.5；中英之间加空格；没有半角标点混用。
6. **克制**：没有第 4 节列的任何一条；一屏只有一个主色在"说话"。
7. **可改**：所有颜色/字号/间距都能通过改 token 生效，页面里没有写死的色值。

## 7. 历史批注：读到就必须处理

批注不再是从画布来的主要输入方式（用户现在直接点元素引用、直接说话），但 `design_status` 仍会返回存量批注：

1. 用户留了批注（出现在 `design_status` 的 `comments[]`，含原文与所属 `frameId`）时，**先读原文与对应 frame 的 HTML**，再动手。
2. 只改批注指到的地方及其必要的连带一致性（例如主色变了，同屏所有主色元素一起变）；不要顺手重做整屏。
3. 改完在回复里逐条对应：批注原文 → 改了什么 → 落在哪个文件。不要处理不了的批注装看不见，说明原因。
4. 改完让用户确认，再进入下一轮。

## 8. 落地到项目

用户点画布上的「落地到项目」（或说"把这个页面写成代码"）时，按 `prompts/design-handoff.md` 的流程执行：读选中 frame 的 HTML 与 token → 跟随项目现有技术栈 → 生成组件文件写进 `src/`（或用户指定目录）→ 返回写入路径。
生成的文件里**不允许**出现指向 `.design/` 的相对路径引用。

## 9. 用户在聊天里直接引用元素时

用户在设计预览里点了一个元素后，聊天输入框里会出现一个 **@ 式引用胶囊**（标签形如「导出 · 订阅订单列表」，即「元素文字 · 屏名」）。用户接着往下写要求、然后发送；**胶囊在发送那一刻展开成下面这段文本，你（模型）看到的就是它**——胶囊只是给人看的短形式，你的定位规则不需要因为胶囊而改变：

```
【设计元素】<屏名>（frame: <frame id>）
元素：<标签名>
选择器：<CSS 选择器>
当前文字：<元素文字，超 40 字会截断>
文件：.design/frames/<frame id>.html
```

看到这段引用时：

1. **先按引用定位，再动手**：`read` 引用里「文件」那一行的路径，用「选择器」在 HTML 里找到那个元素。选择器是 `body > div:nth-of-type(1) …` 这种按结构写死的路径，不要凭「元素」和「当前文字」猜位置。
2. **改法在用户接下来说的那句话里**，两段要一起读。用户只发了引用、还没说要改什么时，先问一句，别自己替他决定。
3. 只改引用指到的那个元素，以及必要的连带一致性（例如主色变了，同屏所有主色元素一起变）；不要顺手重做整屏。
4. 选择器对不上（文件被重写过）时，用元素标签 + 当前文字在文件里搜，改完在回复里说明你实际改的是哪一处。
5. 引用里**没有**颜色、字号、内外边距——用户要点评的是元素本身。需要判断现状就自己读文件或读 `.design/tokens.css`，不要反过来问用户"你要改哪个属性"。

引用偶尔会缺值：帧还没渲染好时可能写成 `元素：(未知元素)`、`选择器：(没有拿到选择器)`、`当前文字：(这个元素没有文字)`。这些是占位词，不是文件里的真实内容，别拿它们去 grep；此时按屏名和用户的话自己 read 文件确认。

两种形态对你没有区别：正常情况是胶囊展开（上面那段文本），胶囊不可用时系统会降级成纯文本引用插进输入框，**展开后的文本完全一样**，你不用去分辨，也不要在回复里提"这次是降级来的"。
